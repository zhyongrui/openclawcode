# 2026-03-31

This log records six borrowing-related slices that were pushed
forward in `openclawcode` today:

1. detached-session provenance for background ACP work
2. runtime tool-surface assembly visibility
3. detached-session resume presentation
4. gateway-backed background current-session entrypoint
5. tool-availability explanation surface
6. borrowing contract/spec documentation for remaining Codex-style boundaries

The intent was not to clone ClaudeCode internals. The intent was to move
selected product and operator-facing patterns onto `openclawcode`'s existing
runtime model.

## What shipped

### 1. Detached/background task provenance became durable and inspectable

The task and flow model now keeps enough metadata to distinguish work that was
spawned as a detached ACP/background session from ordinary foreground activity.

Implemented behavior:

- `TaskRecord` and `FlowRecord` carry `originKind` and `originSessionKey`
- ACP-created detached runs stamp `originKind: "detached_session"`
- SQLite-backed task and flow stores preserve that metadata
- `tasks` and `flows` operator commands now show origin details
- detached ACP work defaults to the clearer operator-facing label
  `"Detached ACP session"`

This is the substrate needed before adding a first-class "background the
current foreground session" UX.

### 2. Effective tool resolution now exposes one runtime assembly summary

Borrowing from ClaudeCode's "single assembly layer" idea, the effective tool
path now has an explicit assembly stage instead of only returning grouped tool
lists.

Implemented behavior:

- `resolveEffectiveToolSurface(...)` now resolves:
  - workspace and agent directories
  - the effective tool set
  - grouped inventory output
  - one structured `assembly` summary
- `assembly` reports:
  - counts by source: `core`, `plugin`, `channel`, `total`
  - runtime context: channel provider, model provider/model id, reply mode,
    owner context
  - runtime flags: subagent binding allowance, explicit-target requirement,
    message-tool disablement
- `tools.effective` now returns that assembly metadata through the gateway
  schema
- `/tools` now renders a `Runtime:` line so operators can see which runtime
  context produced the visible tool surface

This does not yet add a full rollout dashboard or a "why hidden" explanation
surface, but it establishes a concrete boundary for that future work.

### 3. Detached child sessions now expose concrete resume instructions

Borrowing from ClaudeCode's emphasis on resumable detached sessions, the
operator-facing task and flow inspection commands now surface explicit
continuation hints for background child sessions.

Implemented behavior:

- `tasks show` now renders resume metadata for `childSessionKey` sessions
- `flows show` now groups linked child sessions and prints the same resume
  hints
- resume output includes:
  - the stable session key
  - the stored OpenClaw session id when available
  - a concrete `openclaw agent --session-id/--session-key ...` continuation
    command
  - ACP-native hints like `codex resume ...` when ACP identity metadata exists

This does not yet create a first-class "background current session now"
workflow, but it closes a real usability gap after detached child sessions have
already been created.

### 4. `openclaw agent --background` now starts a detached run immediately

Borrowing from ClaudeCode's "background the current work without losing the
session handle" product pattern, the Gateway-backed agent CLI now has an
explicit background mode.

Implemented behavior:

- `openclaw agent` now accepts `--background`
- background mode is gateway-only; `--local --background` is rejected instead
  of silently changing behavior
- background mode sends the normal `agent` RPC with `expectFinal: false` and
  returns as soon as the Gateway acknowledges the run
- the Gateway accepted response now includes the resolved `sessionId` and
  `sessionKey`
- CLI output prints:
  - the accepted `runId`
  - the resolved session identity
  - an `openclaw gateway call agent.wait --run-id ...` command
  - an `openclaw agent --session-id|--session-key ...` continuation command
- `openclaw agent` now also accepts explicit `--session-key <key>` routing, so
  those continuation hints are directly runnable

This still is not a full transcript-handoff UX for an already-interactive TUI
turn, but it establishes a real operator entrypoint for "start this work in the
background and give me immediate recovery handles".

### 5. `/tools` now explains active runtime restrictions

Borrowing from ClaudeCode's operator-first product posture, the tool inventory
surface now does more than list what is available.

Implemented behavior:

- `tools.effective` now returns structured runtime restriction notes
- `/tools` renders those notes as a `Restrictions:` line
- current notes cover concrete runtime gates such as:
  - non-`full` tool profiles hiding capabilities
  - owner-only tools being hidden for non-owner callers
  - explicit-target-only messaging
  - disabled message tools
  - disabled gateway-subagent binding

This closes one of the earlier gaps in the borrowing notes: operators can now
see why a capability is absent without inferring it indirectly from config.

### 6. Remaining Codex-style boundary work is now grounded in contract docs

Borrowing from Codex's contract clarity, the repo now has explicit reference
docs for two previously diffuse areas:

- [Workspace guidance contract](/reference/workspace-guidance-contract)
- [Sandbox and escalation contract](/reference/sandbox-escalation-contract)

The combined tracking document for both ClaudeCode and Codex borrowing work now
lives in:

- [Borrowing delivery plan](/openclawcode/borrowing-delivery-plan)

This does not magically finish the future implementation work, but it removes
the "only exists in chat" failure mode and gives later implementation a stable
spec boundary.

## Follow-up

The next ClaudeCode borrowing steps should build on these narrower substrates
instead of jumping straight to a large opaque feature port:

- add a user-facing "background this session" affordance on top of the new
  detached-session provenance model
- add a clearer operator explanation surface for why a tool is denied,
  gated, or profile-filtered
- keep the borrowing docs updated with explicit implementation status so the
  repo distinguishes "analyzed", "adapted", and "not started"
