# 2026-03-22

Closed one more chat-native setup hardening gap in `/home/zyr/pros/openclawcode`.

- `openclaw code bootstrap --json` now persists explicit repair handoff fields
  when plugin activation or chat setup routing is still blocked:
  - `gatewayRestartCommand`
  - `pluginActivationRepairCommand`
  - `chatSetupCommand`
  - `chatSetupStatusCommand`

  `/occode-setup-status`, so the operator can see:
  - restart the gateway with `openclaw gateway restart`
  - retry setup progress with `/occode-setup-status`

Follow-up Feishu pairing hardening landed the same day:

- unauthorized Feishu DMs in pairing mode now send the pairing retry guidance
  for any slash-style command that needs command authorization, even if plugin
  routing is not yet available for that command
- this closes the silent `/occode-setup` first-touch case where a new operator
  could send the setup command before pairing and receive no feedback

Proactive pairing-before-auth landed later the same day:

- service-start setup kickoff no longer assumes an unpaired DM can jump
  straight into `gh auth login --web`
- when the configured setup target is a pairing-gated `user:*` chat, the plugin
  now creates a setup session in `awaiting-chat-pairing` and proactively pushes
  the pairing code into that same chat
- after pairing approval, the background setup loop automatically starts the
  GitHub device flow and pushes the verification URL/code without waiting for
  `/occode-setup`
- the same runner loop now also keeps scanning configured targets after startup,
  so a newly written repo target can trigger proactive setup without requiring
  a gateway restart first
- `/occode-setup-status` now also reports that setup is blocked on pairing when
  the session has not been approved yet
- updated docs:
  - `docs/openclawcode/README.md`

  - `docs/openclawcode/development-plan-chat-native-autonomy.md`
