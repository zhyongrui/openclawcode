Proactive pairing-before-auth landed later the same day:

- service-start setup kickoff no longer assumes an unpaired DM can jump
  straight into `gh auth login --web`
- when the configured setup target is a pairing-gated `user:*` chat, the plugin
  now creates a setup session in `awaiting-chat-pairing` and proactively pushes
  the pairing code into that same chat
- after pairing approval, the background setup loop automatically starts the
  GitHub device flow and pushes the verification URL/code without waiting for
  `/occode-setup`
- the same runner loop now also keeps scanning configured targets after startup,
  so a newly written repo target can trigger proactive setup without requiring
  a gateway restart first
- `/occode-setup-status` now also reports that setup is blocked on pairing when
  the session has not been approved yet

Preferred operator chat binding landed next:

- OpenClaw now persists one preferred operator DM target per channel/account in
  `operator-chat-targets.json`
- Feishu quick-actions menu events now capture and save `user:<open_id>` into
  that store instead of requiring the operator to send `/occode-setup` first
- Feishu setup wizard copy now tells the operator to tap Quick actions once
  after the gateway is running so the host learns the intended DM target
- `openclaw code bootstrap --mode chatops --chat-target auto` can now reuse
  that preferred operator target even when there is no existing repo binding yet
- the openclawcode plugin now resolves `bind-pending:*` setup placeholders
  through the saved operator target, so proactive pairing/auth kickoff can begin
  without waiting for a manual `/occode-bind`

Provider-pause operator messaging was tightened again after the upstream sync:

- active pause notices in `/occode-status`, `/occode-inbox`, `/occode-start`,
  and `/occode-rerun` now explicitly say:
  - new work can still queue during the pause
  - queued runs will not start until the pause clears
  - queue drain resumes automatically once the pause window elapses
- this closes the remaining operator-facing ambiguity called out in
  `docs/openclawcode/README.md` about what an active provider pause actually
  means for queue behavior and recovery expectations
