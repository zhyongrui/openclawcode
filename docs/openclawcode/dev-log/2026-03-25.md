The important regression discovered after that sync was a plugin runtime/source
skew during local development.

Symptoms seen on a real server checkout:

- `openclaw onboard` loaded plugin source files from the repo checkout:
  - `extensions/feishu/index.ts`
  - `extensions/openclawcode/index.ts`
  - `extensions/qwen-portal-auth/index.ts`
- those plugins then failed during registration with:
  - `TypeError: Cannot read properties of undefined (reading 'resolveEmbeddedSessionLane')`

Why that happened:

- plugin SDK alias resolution already followed the active workspace checkout
  when loading source plugins
- plugin runtime resolution still defaulted to the host CLI package root
- in practice this meant a newer local repo checkout could load against an
  older globally installed `openclaw` runtime
- the mismatch only showed up once newer source expected newer runtime helpers
  such as the embedded-session-lane surface

Fix:

- `src/plugins/loader.ts` now resolves the plugin runtime module with
  `cwd: options.workspaceDir`
- this makes runtime resolution follow the active workspace checkout the same
  way plugin SDK alias resolution already did
- added a regression test in `src/plugins/sdk-alias.test.ts` for the exact
  failure mode:
  - global `openclaw` argv/root points at one package
  - current working directory points at a newer local checkout
  - runtime must come from the workspace checkout, not the global package

Targeted validation passed:

- `pnpm exec vitest run src/plugins/sdk-alias.test.ts --pool threads --reporter=dot`

Development rule captured from this incident:

- when debugging plugin-load failures in a source checkout, do not assume the
  plugin runtime and plugin SDK came from the same OpenClaw package root
- for any loader/path change, treat these three surfaces as one contract:
  - plugin entry resolution
  - plugin SDK alias resolution
  - plugin runtime module resolution
- if one follows the workspace checkout and another follows the global CLI,
  the resulting mixed graph can fail with misleading runtime `undefined`
  property errors instead of a clean version-mismatch message
